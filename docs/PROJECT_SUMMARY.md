# 小球同桌 / Ball Buddy 项目总结

> 汇总日期：2026-10-11（北京时间） · 当前桌面版本：0.3.0 · 共学服务版本：0.2.0

小球同桌是一款 Windows 桌面学习伙伴：把小任务写下来，与持续动画的小球一起专注，完成后获得能量并布置书桌。任务、个人计时、奖励和设置可以离线使用；AI 聊天与任务拆解由使用者配置自己的接口；双人共学连接使用者指定的独立房间服务。

本文记录现有实现和开发决策，适合项目交接。运行方法见 [GETTING_STARTED.md](GETTING_STARTED.md)，模块与数据流见 [ARCHITECTURE.md](ARCHITECTURE.md)，详细历史验收见 [VALIDATION.md](VALIDATION.md)。

## 已实现范围

| 部分 | 当前行为 |
| --- | --- |
| 桌面伙伴 | 连续呼吸、眨眼、形变和缓慢变色；近距离注视鼠标，单击弹跳、双击旋转彩带，拖动放手反馈；悬停或键盘聚焦时显示气泡与操作条 |
| 书桌 | 添加、选择和完成任务；个人专注开始、暂停、继续与结束；完成奖励、能量及桌灯、盆栽、书本布置 |
| 个性化 | 浅色、深色、跟随系统；系统字体或导入 TTF/OTF/WOFF/WOFF2；三档字号；桌宠 70%–150% 大小及灵动、轻柔、静止动作 |
| 窗口 | 关闭时隐藏到托盘或退出；托盘始终提供彻底退出；启动显示、桌宠置顶、提示显示、恢复位置和专注通知设置 |
| AI | 多连接配置、自选 API 地址和模型；OpenAI 兼容 Chat Completions、Anthropic Messages、Gemini 文本协议；流式文字、停止、会话历史与归档 |
| 任务拆解 | 生成最多 12 个建议步骤，允许修改与勾选，再明确确认批量加入；不会自动执行模型生成的命令 |
| 双人共学 | 创建房间与六位邀请码；双方准备、主持人控制的共同专注；两个实时角色、文字消息、招呼、断线暂停、重连和结算去重 |
| 交付 | Windows 便携目录、独立 Node.js 共学服务源码、状态测试与真实 Electron 验收工具 |

首次运行使用空任务列表。软件没有内置账号、订阅或遥测，不默认开机自启，也不读取其他应用、摄像头、麦克风或全局键盘。AI 与共学只在使用者明确操作时联网。

## 技术与结构

- 桌面容器为 Electron 44.7.0；界面为原生 HTML、CSS、JavaScript，主进程与共享逻辑使用 CommonJS。
- Playwright 1.64.0 用于驱动真实 Electron 验收；核心测试使用 Node.js 内置测试运行器。
- 开发环境使用 Node.js 22.12.0+；独立共学服务使用 `ws` 8.18.3，通过 HTTP 健康检查及 WebSocket 房间协议提供服务。
- `src/main/` 管理窗口、托盘、受限 IPC、存储、字体、AI 和共学客户端；`src/shared/` 管理任务、个人计时、奖励与协议校验；`src/renderer/` 负责界面和角色适配。
- `vendor/emotion-ball/` 保留固定版本的第三方源代码和授权；应用新增的动画、眼神、颜色及互动逻辑在 `src/renderer/companion.js` 等适配文件中。
- 运行数据使用 Electron `userData`；测试数据与报告放在不提交的 `artifacts/`，便携输出放在不提交的 `dist/`。

## 关键决策

### 主进程统一提交状态

两个窗口从同一个业务状态读取数据，渲染层通过固定桥发命令。主进程校验调用者和输入，先成功保存，再广播状态并应用原生窗口副作用。共享状态模块保持可单独测试，避免面板、桌宠和计时分别更新造成奖励或显示不同步。

个人计时依赖结束时间戳而非每秒减一，重启时进行状态协调。完成和共学回执均有去重机制；批量任务先整体校验再入库，避免失败时只加入部分步骤。

### 本地持久化分区

任务、计时、统计、布置和偏好保存在版本 1 的 `state.json`；兼容旧记录并保留未知字段。AI 连接、聊天与共学身份独立存储，不混入业务状态，也不通过桌宠快照泄露。有效主记录有备份；坏记录会尽可能保留恢复副本。

API 密钥和房间重连凭据使用 Electron `safeStorage` 加密。系统加密不可用时，凭据只保留在当前进程并提示使用者，不退回明文持久化。聊天和房间消息是本地或服务端的普通记录，不能把“密钥加密”理解为所有文字均已加密。

### 联网与渲染隔离

渲染窗口开启 `contextIsolation` 和 `sandbox`、关闭 `nodeIntegration`，页面 CSP 保持 `connect-src 'none'`。AI 网络请求和共学连接由主进程处理，接口只暴露明确方法；模型结果作为文字或建议，不获得本地执行能力。

共学只同步主动填写的昵称、目标、房间状态、消息和招呼。个人任务列表、AI 私聊、API 密钥、桌面内容与鼠标轨迹不进入房间服务。共学聊天不会自动发送给 AI。

### 服务端掌握共同计时

共学服务拥有唯一轮次与截止时间；断线立即暂停，席位保留 90 秒，恢复后重新准备。服务重启恢复为暂停，停机时间不计入专注。每 5 秒保存计时检查点，异常崩溃可能少计最近未成功落盘的有效时间，不补计停机时间。

客户端收到经认证连接的终态后，先保存待结算回执，再将统计和去重标记同一次写入业务状态，最后清理回执并确认。即使本地保存失败后离开房间，重启也能离线恢复已认证回执；重发不会重复奖励。

### 保留实时角色与可访问交互

角色持续运行动画，而非播放贴图。隐藏、切页或静止时停帧；近距鼠标坐标以至多 25 Hz 采样，仅发桌宠且不记录。桌宠整体 CSS 缩放与原生窗口尺寸同步，避免页面缩放改变鼠标坐标体系。

提示默认自动隐藏，键盘聚焦可以打开；普通鼠标点击留下的焦点不能锁住气泡。主题改版保留单个主球实例与既有操作语义，不复制角色或导入演示数据。

## 已解决的典型问题

| 现象 | 原因与处理 | 后续维护要求 |
| --- | --- | --- |
| 鼠标移开后桌宠提示常驻 | 点击后的焦点误触发显示；增加实际键盘门禁，并配合 `focus-visible` | 分别验普通点击、拖动、Tab 和移出延迟 |
| 最小窗口中大小控件或发送区域被裁切 | 页面总尺寸正常，但内部 `overflow` 祖先裁切 | 同时检查视口与祖先裁切，宽字体和大字号单独验 |
| 字体副本恢复后同 ID 重导入仍失败 | 失败的 `FontFace` Promise 缓存未失效 | 用非持久化 `fontRevision` 通知重试，失败不覆盖已存选择 |
| 桌宠开启置顶后原生窗口仍非置顶 | 当前 Windows 任务栏状态下 Electron 默认 floating 层级未生效 | 仅默认调用失败时使用支持的 `pop-up-menu` 层级兜底；验实际窗口状态 |
| 断线后共学中央仍显示“专注中” | 缓存轮次状态优先于连接状态 | 展示层优先说明等待重连，保留服务计时及权限协议 |
